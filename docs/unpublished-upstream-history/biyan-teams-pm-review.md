# Unpublished 彼岩 Teams product review

> 状态：评审完成，三个战略决定已拍板（2026-06-24）。本文件是分支 A / 分支 B 的依据。

## 已拍板的三个战略决定

1. **默认控制权契约 = 主人说了算（owner-authoritative）。**
   主人动过角色集或用自然语言写了约束，那就是这个团队；主持人（Host）可以重新分派任务，但**未经明确邀请不得自己造角色**。要让 LLM 帮忙组队时，提供一个显式、可见的"让主持人来组队"入口，而不是用静默默认覆盖所有人。
2. **目标用户 = 商业 / 研究通用用户**（分析师、研究、PM 做高风险活），不是开发者高玩。
   推论：去开发者黑话、明确化价值、空状态/默认都按通用用户设计。
3. **Mode 必须是"真有结构"的模式。**
   现有 5 个 mode（接力 / 圆桌 / 红队 等）应全部做成有强制调度/产出结构的真模式，成为真差异化，而不只是提示词味道。这是一个独立的 P1 级硬功能，不放进 P0。

## 一句话结论

引擎有真本事（多模型角色、唱反调的 Skeptic、花钱前的计划闸门），但外壳让它读起来像"更慢的聊天机器人"。两件事同时坏：用户**感知不到**多模型价值；用户**无法信任自己对它的掌控**。底子值得押注，多数修复是接线/文案，不是重构。

## 核心主题：配置"看着说了算，实际只是建议"

所有视角都落到同一条断层线——主人感觉失控。根因是默认姿态"除非触发两种隐藏语法之一，否则团队归 LLM 管"。决定 #1 就是要翻转这个姿态。次要主题：**产品算出来的东西却不告诉用户**（已有 `estimatedCostUsd`、`decision.reason`、token 数、预算耗尽状态，却只显示干巴标题、"$?"、把截断的运行标成"已完成"）。

## 决定记录

**#8 Slice B（本地价格表 → 美元成本估算）—— 主动放弃（2026-06-25）。**

已实现 Slice A：跑完后刷新**真实** provider 余额（用户看到账户真金白银下降）+ 工作区显示 token 用量。`MitaTeamsTokenUsage.estimatedCostUsd` 字段仅在 **provider 自身 API 返回成本**时填充，并无本地价格表，当前也不展示。

不做 Slice B 的理由：

1. **Slice A 已准确回答"花了多少钱"** —— 真实余额变化比任何估算都可信；估算反而是退步。
2. **价格表是持续维护的坑** —— 供应商频繁改价/加模型，价格过期就显示"自信但错误"的美元数，**摧毁**本要建立的成本信任。"不显示"优于"显示错的"。
3. **覆盖不全** —— 支持大量 provider + 自定义/代理/本地模型，价格表覆盖不到 → 这些显示空白或错误，看似坏掉。
4. **目标用户（商业/研究）不需要这个精度** —— "这次贵不贵"用余额变化 + token 数已足够；逐次美元估算是 power-user 功能。

若未来确有"跑前看成本"诉求，**更便宜安全**的做法是审批卡上的定性提示（如"这个团队有 N 个角色，多轮运行更费"，零维护、不会过期），而非维护价格表。
